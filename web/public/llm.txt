# mailrs - AI Email API

> Full-featured email server API: send, read, search, reply, manage accounts/domains/aliases/groups — via MCP or REST.

Base URL: https://mail.golia.ai
Auth: Bearer API key or session token on all requests
Full API docs: https://mail.golia.ai/llm-full.txt
Interactive docs: https://mail.golia.ai/docs.html
OpenAPI spec: https://mail.golia.ai/openapi.json

## REST API

### Email
- POST /api/mail/send — send email (JSON)
- POST /api/mail/send-multipart — send with attachments; `draft_id` sends a saved draft with its files and deletes it once queued; such a send over the 50 MiB message limit gets a 413 naming which attachments to drop
- GET/POST /api/mail/drafts, DELETE /api/mail/drafts/{id} — drafts; `attachments` names files uploaded with POST /api/mail/draft-attachments (absent keeps them, [] removes them); GET lists drafts with files only with ?with_attachments=true
- POST /api/mail/draft-attachments (multipart `file`), GET /api/mail/draft-attachments/{blob_id} — a draft's files, your own only
- POST /api/mail/unsubscribe — RFC 8058 one-click leave; body names the message, the server posts to the URL that message carried
- GET /api/conversations — list conversations (?category=, ?folder=, ?limit=, ?cursor= the last row's `cursor` for the next page)
- GET /api/conversations/search?q=keyword — search, scoped to a list by the same parameters GET /api/conversations takes (folder, category, archived, trashed, label, pinned, snoozed, section, assigned_to_me, unread, starred, include_quarantined, accounts; ?quarantined=true searches Review) plus ?limit=; q takes operators: from:, to:, subject:, has:attachment, after:YYYY-MM-DD, before:YYYY-MM-DD, label:<name>, is:unread|read|starred|pinned, in:inbox|archive|junk|trash|sent|starred|anywhere, and - to negate
- GET/POST /api/saved-searches, DELETE /api/saved-searches/{id} — your saved searches ({name, query})
- GET /api/auth/sessions, DELETE /api/auth/sessions/{id}, POST /api/auth/sessions/end-others — your signed-in sessions (ip, user agent, last used) and signing them out
- GET/POST /api/auth/app-passwords, DELETE /api/auth/app-passwords/{id}, POST /api/auth/app-passwords/revoke-all — app passwords for mail apps (made after a recent password confirmation; shown once)
- GET/PUT /api/settings/vacation — vacation reply {enabled, subject, body, start, end, days}; GET/POST/DELETE /api/settings/forwarding, POST /api/settings/forwarding/verify {code} — forwarding to an address elsewhere, on once the code mailed there is entered (POST needs a recent password confirmation)
- GET/PUT /api/settings/swipe — what a swipe on a conversation row does {left, right}, each archive / trash / read / none; right archive, left trash when never set
- GET/PUT /api/settings/sectioned-inbox — whether the Inbox is split into sections (all, to reply, waiting, new senders) {enabled}; on when never set
- GET/POST /api/rules, POST/DELETE /api/rules/{id} — rules {name, query, actions, enabled}: arriving mail matching the query gets the actions (label:<id>, archive, read, star, junk, trash); POST /api/rules/preview {query} counts what a run would change; POST /api/rules/{id}/apply runs one over existing mail and returns run_id; POST /api/rules/runs/{run_id}/undo reverses it (7 days)
- GET/POST /api/masked-emails, PATCH/DELETE /api/masked-emails/{email} — masked addresses: a random address per site that delivers to you ({forDomain, description}); state enabled / disabled / deleted (deleted is for good and never reissued); replies sent from one keep your own address out of every header. JMAP `MaskedEmail/get` and `MaskedEmail/set` (capability https://www.fastmail.com/dev/maskedemail) do the same; a `masked_email` agent key reaches only these
- POST /api/alias/random/new[?hostname=] (SimpleLogin's call, key in an `Authentication` header, {note} → 201 {alias}) and POST /api/v1/aliases (addy.io's call, Bearer key, {domain, description} → 201 {data: {email}}; a domain you may not use is 422) — make a masked address from a password manager such as Bitwarden; only a `masked_email` key is accepted
- GET /api/conversations/{thread_id} — thread messages
- GET /api/mail/messages/{uid} — read message; a meeting invitation comes back as `invite_method` + `invite_payload`
- POST /api/invites/{uid}/rsvp — answer an invitation (ACCEPTED / TENTATIVE / DECLINED); records the choice on the calendar event and queues an iTIP REPLY to the organiser
- POST /api/invites/{uid}/counter — propose a different time
- GET /api/calendar/conflicts?start=&end= — what else is already in the calendar over that window (declined invitations are not conflicts)
- GET /api/calendar/events?start=&end= — every event in that window: own, invitations filed from mail with the reader's answer (`partstat`), and subscribed feeds; a recurring event comes back once per occurrence (same `uid`, each with its `recurrence_id`)
- POST /api/conversations/{thread_id}/read — mark read
- POST /api/conversations/mark-all-read — mark read every conversation of the list named by the same parameters GET /api/conversations takes (?quarantined=true marks Review); with no list named, the whole mailbox except held mail. The MCP mark_all_read tool takes no list and marks the whole mailbox
- POST /api/conversations/{thread_id}/star — star
- POST /api/conversations/{thread_id}/archive — archive
- DELETE /api/conversations/{thread_id} — move thread to the Trash (deleted for good after 30 days)
- POST /api/conversations/{thread_id}/untrash — restore from the Trash
- DELETE /api/conversations/{thread_id}/forever — delete for good (recent password confirmation)
- POST /api/trash/empty — delete everything in the Trash for good (recent password confirmation)
- GET /api/conversations?trashed=true — list the Trash
- GET/POST /api/labels, POST/DELETE /api/labels/{id} — your labels
- GET /api/storage — {used_bytes, quota_bytes}: how much of your quota your mail takes (quota_bytes is null when there is none); only imports stop at the quota, sending always goes out
- POST/DELETE /api/conversations/{thread_id}/labels/{id} — put a label on or take it off
- GET /api/conversations?label={id} — one label's conversations
- POST /api/mail/sends/{send_id}/cancel — stop a send that has not gone out. Returns jobs_removed / recipients_cancelled / already_delivered; a recipient an MX already accepted is NOT recalled. 409 if the send has finished
- GET /api/quarantine — conversations held as suspected fraud, newest first. Kept, not deleted, and out of every other list — including its counts
- POST /api/quarantine/{thread_id}/release — it was not fraud; returns the conversation to its list
- POST /api/messages/{message_id}/report — report it as a scam: your copy is held at once, and so are your other copies of the same template (no ground needed; a conversation you put back is held again only for a copy that came after); other people's copies of the same template from the last thirty days are taken back into Review when there is a ground (a super administrator's report, two different people within a day, or a hold-level rule of the rules running when it is reported, named in `hold_rule` with the rule set's `rules_version`) and nothing says to wait (over 20 inboxes, a sender we have heard from for over 90 days, an allow-listed sender), else an administrator decides. A body under eight words has no fingerprint: nothing else is looked for, `no_fingerprint` is true, and the case is counted in `/api/health` → `fraud_hits` as `report-no-fingerprint`. Returns {report_id, state: taken_back|none_found|waiting|dismissed, taken_back, own_held, inboxes, grounds, waits, no_fingerprint, hold_rule, rules_version, at, decided_at}; GET /api/reports/{report_id} for where your own report stands
- GET /api/admin/reports/pending, POST /api/admin/reports/{report_id}/confirm (recent password confirmation) or /dismiss — the reports whose copies wait, with the reported message's subject, sender and sender domain and up to ten copies (super administrators)
- GET /api/messages/{message_id}/fraud-verdict — the four layers that decided it (transport / identity / provenance / content), as they were decided, with the rule-set version. `{"verdict": null}` when nothing was found
- GET /api/conversations?include_quarantined=true — show held conversations in place, marked. Default off; the exclusion is in the query shape, so held conversations are out of the totals too
- GET /api/mail/folders — list folders
- GET /api/mail/export — All Mail (everything but Junk and the Trash) as an mboxrd stream; each message carries X-Mailrs-Folder and Status: RO when read (recent password confirmation)
- POST /api/mail/import — body is an mbox (an export from here, a Gmail Takeout, or any mbox); filed message by message, mail you wrote into Sent, the rest into the Inbox, read and archived as the file says; Junk and Trash skipped, a Message-ID already here not filed twice; no filters, forwarding, webhooks or notifications run. A message over 50 MiB is skipped (too_large). Imports stop at the quota, sending never does: once the mailbox is full the import stops with over_quota true and complete false; free space and run it again, what is already here is skipped. Returns {imported, sent, archived, held, skipped_duplicate, skipped_junk_or_trash, too_large, failed, over_quota, complete}
- POST /api/mail/import/imap {host, port, username, password} — import from another provider over IMAP (993, or 143 with STARTTLS; certificates verified); the password is used once and never stored; progress is, so starting again resumes. One import per user at a time, five starts a day; the same 50 MiB and quota limits as the mbox import. GET for where it stands ({state: queued|running|done|failed|cancelled|interrupted|none, host, port, username, folder, report, error}, report as above), DELETE to stop after the message in hand
- GET /api/contacts — search contacts
- JMAP: GET /.well-known/jmap, POST /jmap/api/, WebSocket /jmap/ws/ (subprotocol jmap) — mail, submission (held sends up to 30 days, cancel while held), vacation reply, search snippets, masked addresses

### Admin (requires permissions)
- GET/POST/DELETE /api/admin/domains — domain CRUD
- GET/POST/DELETE /api/admin/accounts — account CRUD
- GET/POST/DELETE /api/admin/aliases — alias CRUD
- GET/POST/DELETE /api/admin/email-groups — email group CRUD + /members
- PUT /api/admin/email-groups/{id}/shared — make a group a team inbox (`{"shared": true}`) or a plain list again
- GET /api/admin/shared/{gid}/{conv}/deleted-notes/{id} — what a deleted team note said; super administrators only, each read written to the audit log
- GET/POST/DELETE /api/admin/groups — group CRUD + /permissions + /members
- GET /api/admin/permissions — list all permissions
- GET /api/admin/dmarc/reports — inbound DMARC aggregate reports, newest first (?limit=) (admin.domains)
- GET /api/admin/dmarc/sources — per-source-IP rollup with alignment rate (?domain=, ?days=) (admin.domains)
- GET/POST /api/admin/greylist/local-lists, DELETE /api/admin/greylist/local-lists/{id} — local greylist white/black CRUD (admin.greylist)
- GET /api/admin/flow — where mail is right now: receiving, spool backlog, outbound queue (queued / retrying / scheduled / failed), mock mail
- GET /api/admin/push-stats?days=14 — pushes per channel (apns / web / unifiedpush) per UTC day, summed over every account: sent, failed, suppressed_policy (held by push settings), suppressed_quiet (held in quiet hours); any admin permission
- GET /api/admin/mock, PUT /api/admin/mock/settings — mock mail usage and settings (on/off, retention days, per-namespace and total limits, namespaces per person, who may create); an admin lists everyone's namespaces with GET /api/mock/namespaces?all=true
- POST /api/admin/accounts/{address}/password — a new password, the account's sessions signed out; with `{"compromised":{"revoke_key_ids":[...]}}` (every key id the list below shows) all its agent keys are revoked too (admin.accounts, recent confirmation)
- POST /api/admin/accounts/{address}/restore — a deleted account back, before its purge, with its mail, settings and group memberships; body `{"parked": "<delete time>"}` only for an address deleted more than once (super administrator, recent confirmation; 200 `{rescheduled, returned_as_drafts}`: withheld sends back to their time, or back as unsent drafts when their time passed; 409 `{refused, parked}`)
- GET /api/admin/accounts/{address}/agent-keys — an account's agent keys with created and last-used times (admin.accounts, recent confirmation)
- GET /api/admin/outbound/paused, POST /api/admin/outbound/paused/{address}/resume — accounts whose outbound mail is paused after unusual sending, and releasing one with its held mail sent or discarded (super administrator)
- GET /api/admin/ops/state, GET /api/admin/ops/history, POST /api/admin/ops/silences, POST /api/admin/ops/silences/{id}/end, POST /api/admin/ops/maintenance — the ops daemon as webapi sees it (`reach` says whether it was reached), its last day of changes, and silences and maintenance, which need an end and a reason (super administrator; changes need a recent confirmation)
- A send from a paused account answers 423 `outbound_paused`; SMTP submission answers 550 5.7.1 at MAIL FROM
- GET/PUT /api/admin/accounts/{address}/forwards — other accounts here that get a copy of everything delivered to an account, written straight into their mailboxes (admin.accounts)
- GET/PUT /api/admin/accounts/{address}/send-as — the addresses an account was granted to send as, besides its own, its aliases and its email groups (admin.accounts)
- GET /api/admin/auth-events — sign-in attempts on every way in (web, verify, IMAP, POP3, SMTP, ManageSieve, DAV, API keys), newest first; filter with account, source, result, channel, since, until, limit (admin.accounts)
- POST /api/admin/reconcile-maildir — count mailboxes and message files under the maildir root; read-only (admin)

### Mock mail (disposable test mailboxes)
Addresses `{namespace}.{any-tag}@mock.golia.jp` receive mail that never reaches a real mailbox; nothing is ever sent outward from them. Kept 3 days, 500 messages per namespace. An agent key with scope `mock` (or `mock:{namespace}`) reaches only this.
- GET/POST /api/mock/namespaces, DELETE /api/mock/namespaces/{ns} — namespaces (10 per user)
- POST /api/mock/namespaces/{ns}/addresses — hand out an address (`{"tag": "..."}` optional)
- GET /api/mock/namespaces/{ns}/messages — list (?tag=&tag_prefix=&to=&from=&subject=&since=&limit=), each with extracted `codes` and `links`
- GET /api/mock/namespaces/{ns}/messages/wait — wait up to 60 s for the next one (?tag=&since=&timeout=), returned whole
- GET /api/mock/namespaces/{ns}/messages/latest, /messages/{id}, /messages/{id}/raw
- DELETE /api/mock/namespaces/{ns}/messages/{id}, DELETE /api/mock/namespaces/{ns}/messages?tag=
- POST /api/mock/namespaces/{ns}/send — send from the namespace; only mock recipients receive it
- POST /api/mock/namespaces/{ns}/smtp-token — SMTP password for `{ns}@mock.golia.jp` on 587: everything that login sends is kept in the namespace, never delivered
- PUT/DELETE /api/mock/namespaces/{ns}/webhook — POST every new message to a URL (`{"url": "https://…"}`; event `mock_message`, signed like other webhooks)
- IMAP: log in as `{ns}@mock.golia.jp` with the SMTP password to read the namespace read-only (INBOX)
- Fixed-result addresses: mail to `bounce@`, `ooto@`, `delay@`, `complaint@mock.golia.jp` (also `+tag`) answers the sender with a bounce, an out-of-office reply, a delay notice or an abuse report — in the sender's own INBOX, or in the namespace for sandbox and `send` mail. Nothing reaches the suppression list
