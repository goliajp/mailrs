## REST API

### Email
- POST /api/mail/send — send email (JSON)
- POST /api/mail/send-multipart — send with attachments
- POST /api/mail/unsubscribe — RFC 8058 one-click leave; body names the message, the server posts to the URL that message carried
- GET /api/conversations — list conversations (?category=, ?folder=, ?limit=)
- GET /api/conversations/search?q=keyword — full-text search (also ?category=, ?folder=, ?limit=)
- GET /api/conversations/{thread_id} — thread messages
- GET /api/mail/messages/{uid} — read message; a meeting invitation comes back as `invite_method` + `invite_payload`
- POST /api/invites/{uid}/rsvp — answer an invitation (ACCEPTED / TENTATIVE / DECLINED); records the choice and queues an iTIP REPLY to the organiser
- POST /api/invites/{uid}/counter — propose a different time
- GET /api/calendar/conflicts?start=&end= — what else is already in the calendar over that window
- POST /api/conversations/{thread_id}/read — mark read
- POST /api/conversations/{thread_id}/star — star
- POST /api/conversations/{thread_id}/archive — archive
- DELETE /api/conversations/{thread_id} — move thread to the Trash (deleted for good after 30 days)
- POST /api/conversations/{thread_id}/untrash — restore from the Trash
- DELETE /api/conversations/{thread_id}/forever — delete for good (recent password confirmation)
- POST /api/trash/empty — delete everything in the Trash for good (recent password confirmation)
- GET /api/conversations?trashed=true — list the Trash
- GET/POST /api/labels, POST/DELETE /api/labels/{id} — your labels
- POST/DELETE /api/conversations/{thread_id}/labels/{id} — put a label on or take it off
- GET /api/conversations?label={id} — one label's conversations
- POST /api/mail/sends/{send_id}/cancel — stop a send that has not gone out. Returns jobs_removed / recipients_cancelled / already_delivered; a recipient an MX already accepted is NOT recalled. 409 if the send has finished
- GET /api/quarantine — conversations held as suspected fraud, newest first. Kept, not deleted, and out of every other list — including its counts
- POST /api/quarantine/{thread_id}/release — it was not fraud; returns the conversation to its list
- GET /api/messages/{message_id}/fraud-verdict — the four layers that decided it (transport / identity / provenance / content), as they were decided, with the rule-set version. `{"verdict": null}` when nothing was found
- GET /api/conversations?include_quarantined=1 — show held conversations in place, marked. Default off; the exclusion is in the query shape, so held conversations are out of the totals too
- GET /api/mail/folders — list folders
- GET /api/contacts — search contacts

### Admin (requires permissions)
- GET/POST/DELETE /api/admin/domains — domain CRUD
- GET/POST/DELETE /api/admin/accounts — account CRUD
- GET/POST/DELETE /api/admin/aliases — alias CRUD
- GET/POST/DELETE /api/admin/email-groups — email group CRUD + /members
- GET/POST/DELETE /api/admin/groups — group CRUD + /permissions + /members
- GET /api/admin/permissions — list all permissions
- GET /api/admin/dmarc/reports — inbound DMARC aggregate reports, newest first (?limit=) (admin.domains)
- GET /api/admin/dmarc/sources — per-source-IP rollup with alignment rate (?domain=, ?days=) (admin.domains)
- GET/POST /api/admin/greylist/local-lists, DELETE /api/admin/greylist/local-lists/{id} — local greylist white/black CRUD (admin.greylist)
- GET /api/admin/flow — where mail is right now: receiving, spool backlog, outbound queue (queued / retrying / scheduled / failed), mock mail
- GET /api/admin/mock, PUT /api/admin/mock/settings — mock mail usage and settings (on/off, retention days, per-namespace and total limits, namespaces per person, who may create); an admin lists everyone's namespaces with GET /api/mock/namespaces?all=true
- POST /api/admin/accounts/{address}/password — a new password, the account's sessions signed out; with `{"compromised":{"revoke_key_ids":[...]}}` (every key id the list below shows) all its agent keys are revoked too (admin.accounts, recent confirmation)
- GET /api/admin/accounts/{address}/agent-keys — an account's agent keys with created and last-used times (admin.accounts, recent confirmation)
- GET /api/admin/outbound/paused, POST /api/admin/outbound/paused/{address}/resume — accounts whose outbound mail is paused after unusual sending, and releasing one with its held mail sent or discarded (super administrator)
- A send from a paused account answers 423 `outbound_paused`; SMTP submission answers 550 5.7.1 at MAIL FROM
- GET/PUT /api/admin/accounts/{address}/forwards — other accounts here that get a copy of everything delivered to an account, written straight into their mailboxes (admin.accounts)
- GET/PUT /api/admin/accounts/{address}/send-as — the addresses an account was granted to send as, besides its own, its aliases and its email groups (admin.accounts)
- GET /api/admin/auth-events — sign-in attempts on every way in (web, verify, IMAP, POP3, SMTP, ManageSieve, DAV, API keys), newest first; filter with account, source, result, channel, since, until, limit (admin.accounts)
- POST /api/admin/reconcile-maildir — count mailboxes and message files under the maildir root; read-only (admin)

### Mock mail (disposable test mailboxes)
Addresses `{namespace}.{any-tag}@mock.golia.jp` receive mail that never reaches a real mailbox; nothing is ever sent outward from them. Kept 3 days, 500 messages per namespace. An agent key with scope `mock` (or `mock:{namespace}`) reaches only this.
- GET/POST /api/mock/namespaces, DELETE /api/mock/namespaces/{ns} — namespaces (10 per user)
- POST /api/mock/namespaces/{ns}/addresses — hand out an address (`{"tag": "..."}` optional)
- GET /api/mock/namespaces/{ns}/messages — list (?tag=&tag_prefix=&to=&from=&subject=&since=&limit=), each with extracted `codes` and `links`
- GET /api/mock/namespaces/{ns}/messages/wait — wait up to 60 s for the next one (?tag=&since=&timeout=), returned whole
- GET /api/mock/namespaces/{ns}/messages/latest, /messages/{id}, /messages/{id}/raw
- DELETE /api/mock/namespaces/{ns}/messages/{id}, DELETE /api/mock/namespaces/{ns}/messages?tag=
- POST /api/mock/namespaces/{ns}/send — send from the namespace; only mock recipients receive it
- POST /api/mock/namespaces/{ns}/smtp-token — SMTP password for `{ns}@mock.golia.jp` on 587: everything that login sends is kept in the namespace, never delivered
- PUT/DELETE /api/mock/namespaces/{ns}/webhook — POST every new message to a URL (`{"url": "https://…"}`; event `mock_message`, signed like other webhooks)
- IMAP: log in as `{ns}@mock.golia.jp` with the SMTP password to read the namespace read-only (INBOX)
- Fixed-result addresses: mail to `bounce@`, `ooto@`, `delay@`, `complaint@mock.golia.jp` (also `+tag`) answers the sender with a bounce, an out-of-office reply, a delay notice or an abuse report — in the sender's own INBOX, or in the namespace for sandbox and `send` mail. Nothing reaches the suppression list
